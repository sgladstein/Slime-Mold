## Rules
1. **Book before you run.** (The runner thread runs it for you; see above.) Add a line under "Queue" (thread, kind, what, expected minutes). Re-read this file just before you edit it (others write it too), and again about 10 s after.
2. **A timing run gets the PC to itself.** While a timing run is "running", nothing else runs on the PC: no census, no build, no campaign.exe.
3. **Censuses and other long CPU or GPU runs** go only when no timing run is running or queued ahead of them. Put them at the back of the queue. A census already running when a timing run is booked finishes its current batch and then waits.
4. **Each timing output starts with the bench's machine line** (added in e516f4f). Timings without that line, or taken while anything else ran, don't count.
5. **Use your own worktree** (e.g. `C:\Users\Scott\Code\Slime Mold GPU`). Never switch HEAD in another thread's checkout, and never in `C:\Users\Scott\Code\Slime Mold` while someone else's run is using it.
6. **When you finish,** move your line to "Done" with the end time, and message the next thread in the queue.
7. Check free memory and disk space before you start (keep 2-3 GB free on C:). **One job at a time:** the PC has 8 GB of RAM, and the 15:23-16:00Z overlap ran it out (two campaign censuses crashed with "memory allocation failed"). Start a job only when more than 3 GB of RAM is free (pc-batch: 2 GB, with two build jobs, since the owner's apps leave 2.0-2.3 GB; integration 11-14 08:45Z). Never delete the owner's files.
